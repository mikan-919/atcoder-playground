# ABC382 C Kaiten Sushi

## 詰まったところ

人を美食度順に並べると、元の列で誰が先に食べるかという情報が失われるように見えた。各寿司について候補を集め直すと、計算量が `O(NM)` になるところでも詰まった。

## 想定解

寿司 `B` の答えを「`A_i <= B` を満たす元の人番号 `i` の最小値」と言い換える。人と寿司を値の昇順に並べ、条件を満たした人を添字で一度ずつ追加し、元の人番号の最小値を保つ。

## なぜそこに気づけなかったか

美食度による並べ替えを、実際に寿司を食べさせる順番だと捉えていた。候補に入る順番は美食度、食べる優先順位は元の人番号、出力順は元の寿司番号という役割を分離できていなかった。

## 次に見たら思い出すこと

`A <= x` を何度も聞かれたら、`x` を昇順にして要素を一度ずつ解禁し、必要な最小値・最大値・個数・合計だけを保つ。
